# 警情处置控制台页面设计

## 设计目标

页面是一张高密度警情处置工作台，不是大屏展示页，也不是产品说明页。

页面服务四类核心活动：

- 接收警情事件，并由指挥长决定是否处置。
- 展示任务成功产出的业务卡片。
- 在同一个侧边区域内切换协作、待办、历史。
- 通过底部指令坞补充指令、上传材料、语音输入或发送命令。

视觉气质保持冷静、克制、可靠、可扫读。所有层级都服务于警情、任务、消息、卡片和指令，不使用营销式 hero、大面积装饰渐变、装饰光斑或抽象背景。

## 页面结构

页面由五个固定区域组成：

- 左侧细栏。
- 顶部状态栏。
- 业务卡片工作区。
- 可吸附侧边区域。
- 底部指令坞。

左侧细栏固定在最左侧。侧边区域可收纳、展开、吸附到左侧或右侧。吸附到左侧时，侧边区域位于左侧细栏右侧，不覆盖细栏。

业务卡片工作区和侧边区域共享主体空间。侧边区域展开时，卡片工作区缩窄；侧边区域收起时，卡片工作区占满主体宽度。

切换协作、待办、历史时，只替换侧边区域内部内容。侧边区域的外壳、宽度、吸附方向和收纳状态保持稳定。

## 左侧细栏

左侧细栏是全局模式入口，宽度保持紧凑。

细栏内垂直放置五个图标控件：

- 协作。
- 待办。
- 历史。
- 语音输入。
- 指令输入。

细栏控件使用图标、状态条、背景和 hover 反馈表达含义，不在栏内直接展示文字 label。文字只用于 tooltip、`aria-label` 或悬浮提示。

控件行为：

- 点击协作、待办、历史：展开侧边区域并切换对应内容。
- 点击语音输入：切换收音状态样式。
- 点击指令输入：切换底部指令坞；展开和收起都从底部运动。

激活项使用克制的选中态，例如左侧亮条、按钮背景提亮、图标颜色变化。

## 顶部状态栏

顶部状态栏横跨左侧细栏以外的主区域，保持低高度和高信息密度。

顶部状态栏展示产品身份：

- 紧凑的警务符号或系统图标。
- 短标题产品名。
- 不展示说明性副标题、功能说明或教学文案。

顶部栏不承载大段警情详情，不挤压卡片区和侧边区。全局工具只保留必要图标按钮，按钮尺寸、边框、hover 和 active 反馈保持一致。

## 警情入口

页面待接入状态下：

- 业务卡片工作区为空。
- 侧边区域默认收纳。
- 底部指令坞默认隐藏。
- 页面显示一个新的警情事件入口。

警情入口像真实系统通知：

- 有警情标题、摘要、时间或来源。
- 有“处置”和“不处置”两个明确动作。
- 层级高于背景，但不遮挡顶部栏和主要工作区。
- 体积小于主工作台区域。

用户点击“处置”后：

- 警情入口退场。
- 处置上下文切换为该警情。
- 协作内容进入处置流。
- 任务成功后逐步生成业务卡片。

用户点击“不处置”后：

- 警情入口退场。
- 该警情进入待办或记录为已不处置状态。
- 页面保持待接入或队列查看状态。

## 业务卡片工作区

业务卡片工作区展示任务成功产出的业务结果。

卡片生成规则：

- 初始为空。
- 任务成功且有可视业务结果时生成卡片。
- 任务失败时不生成空卡片。
- 成功任务只更新任务状态和对应卡片，不在协作流额外刷一条长消息。

卡片内容使用业务语言，不展示工程字段。

卡片标题示例：

- 事发地址定位。
- 处置预案。
- 周边监控。
- 报警人背景。
- 周边警力。

卡片布局：

- 侧边区域展开时，卡片区水平分为三列。
- 侧边区域收起时，卡片区水平分为四列。
- 普通卡片占一列一行。
- 普通卡片高度固定为 200px。
- 窄视口下卡片降级为更少列数，避免横向溢出。

卡片头部：

- 左侧是标题和一行业务摘要。
- 右侧只放图形按钮。
- 按钮顺序为：收起、最大化或还原、关闭。
- 收起按钮只保留入口，不定义收起行为。
- 最大化按钮点击后进入卡片区最大化，再次点击还原。
- 关闭按钮隐藏该卡片，但不改变任务状态或任务结果。
- 图形按钮有统一尺寸、hover 反馈和可访问名称。

卡片选中态：

- 选中卡片有清晰边框或背景差异。
- 选中态联动对应任务和协作流节点。

卡片关闭和恢复：

- 关闭卡片只是隐藏卡片。
- 已关闭卡片可通过对应任务行右侧的“打开卡片”图标按钮恢复。
- 关闭最大化卡片时，同时退出最大化状态。

卡片最大化：

- 最大化只覆盖业务卡片工作区。
- 最大化使用卡片区的可用宽度和高度。
- 最大化不得覆盖左侧细栏、顶部状态栏或可吸附侧边区域。
- 最大化状态下仍保留还原按钮和关闭按钮。
- 同一时间只展示一个最大化卡片。

卡片区滚动：

- 卡片区内容可滚动。
- 滚动时不显示滚动条。
- 卡片区保留底部安全距离，最后一张卡片不进入指令坞高度。
- 指令坞不遮挡卡片头部操作按钮。

## 侧边区域

侧边区域是可吸附的工作台抽屉。

基础行为：

- 默认收纳。
- 小浮动把手可点击展开。
- 右上角图标按钮可收起。
- 顶部可拖拽切换左侧或右侧吸附。
- 收纳后保留小浮动把手。

拖拽规则：

- 拖拽侧边区域顶部时，指针移动到视口左半边吸附到左侧。
- 指针移动到视口右半边吸附到右侧。
- 吸附方向只改变侧边区域位置，不改变内部内容状态。

收纳把手：

- 贴近吸附边。
- 右侧吸附时位于右边缘。
- 左侧吸附时位于左侧细栏右边。
- 可点击展开。
- 有 hover、active 和拖拽反馈。
- 不展示长文字。

侧边区域内部有三种内容：

- 协作。
- 待办。
- 历史。

三种内容共用同一个侧边区域，切换时整体替换内部内容，不叠加，不打开新面板。

## 协作

协作是统一的处置流，不拆分为多个上下区域。

处置流承载三类来源：

- 用户。
- 警情消息事件。
- 每一个任务的状态和失败结果。

协作流按事件生命周期组织，而不是按聊天消息堆叠。

协作流的业务步骤使用真实名称，例如：

- 警情要素识别。
- 基础研判。
- 现场态势展开。
- 出警资源可视化。

警情消息通知和处置动态之间有一个独立步骤：

- 标题为“根据警情匹配预案指引”。
- 匹配成功时继续渲染处置动态。
- 未匹配时显示“暂未匹配到预案”，且不渲染处置动态整块。
- 该步骤不是普通任务行。

任务状态：

- 每个步骤包含多个任务。
- 任务状态包括等待、执行中、已完成、失败、已停止。
- 默认行内不展示可见中文状态 label。
- 状态由图标、节点形态、边框、透明度和颜色表达。
- 中文状态语义保留在数据、`aria-label`、tooltip 或详情层中。
- 成功任务只更新状态和卡片。
- 失败任务展开失败信息。

协作流滚动：

- 协作流内容可滚动。
- 滚动时不显示滚动条。

用户主动发指令时：

- 用户消息统一显示为“我”。
- 系统响应接在用户消息之后。
- 指令坞发送成功后，用户输入内容真实追加到协作流中，不只清空输入框。

有卡片的任务：

- 已完成且有关联卡片的任务，在任务行右侧展示“打开卡片”图标按钮。
- 图标使用卡片或面板加箭头语义，不使用文字按钮。
- 按钮有 `aria-label` 和 title，例如“打开卡片：事发地址定位”。
- 点击按钮只恢复、定位并高亮对应卡片，不唤出指令坞。
- 点击按钮不触发任务行自身的选中或指令坞行为。
- 已关闭的卡片可通过该按钮恢复。
- 没有关联卡片或卡片尚未可用的任务不展示该按钮。

## 失败任务处理

失败任务提供轻量补救入口。

失败任务行：

- 有明显失败状态。
- 可被选中。
- 展示失败信息。
- 右侧提供重试按钮。
- 点击任务行唤出底部指令坞。
- 指令坞展示引用 chip，例如“引用：跟踪出警警车 · 失败”。

输入框只保留用户的新指令，不自动写入原任务内容或失败信息。

## 待办

待办展示警情事件队列，不展示处置流内部任务。

待办是列表。默认每项只展示固定长度摘要；点击选中后，在该列表项内部展开完整内容。待办不打开独立详情页，也不覆盖卡片区。

待办状态：

- 指挥长某某处置中。
- 等待处置。
- 已不处置。

待办动作：

- 协同处置。
- 处置。

状态表达不只靠文字，同时使用状态条、状态节点、按钮强弱、透明度或边框：

- 处置中：状态条更亮，边框更强，动作按钮为“协同处置”。
- 等待处置：中等对比，动作按钮为“处置”。
- 已不处置：整体弱化，仍可查看完整内容，也允许点击“处置”重新进入协作区。

点击待办中的“处置”后：

- 侧边区域切换回协作。
- 处置上下文切换到该警情。
- 协作流出现新的警情消息通知和指挥长开始处置内容。
- 已不处置警情也支持重新处置。

## 历史

历史展示已处置会话列表。

历史也是列表。默认每项只展示固定长度摘要；点击“处置回放”进入只读回放。

历史回放规则：

- 回放是只读状态。
- 不允许继续处置。
- 不允许基于历史直接发指令。
- 点击处置回放后，处置上下文、卡片区、协作流切换到该历史快照。
- 指令坞隐藏或禁用。

历史视觉语言更安静，避免和处置中的警情竞争注意力。

## 指令坞

指令坞位于页面底部，是浮动输入控制条。

唤出方式：

- 点击左侧细栏的指令输入控件。
- 点击任务行。
- 点击失败或已停止任务。
- 点击重试按钮。

显示规则：

- 左侧细栏的指令输入控件是显式 toggle：点击展开，再次点击收起。
- 指令坞展开和收起都从底部运动。
- 历史只读状态下，指令坞隐藏或不可打开。
- 绑定失败或已停止任务时，引用 chip 展示绑定对象。

指令坞结构：

- 引用 chip。
- 输入框。
- 上传文件按钮。
- 语音输入按钮。
- 发送按钮。

指令坞视觉：

- 大圆角容器。
- 深色浮层。
- 位于卡片区前层，保留分层关系。
- 容器半透明并使用背景模糊，使卡片区仍有透出感。
- 输入区和按钮在同一个连续容器内。
- 上传、语音、发送按钮是紧凑图标控件。
- 发送按钮使用更强主操作样式。

输入框：

- 单行起步。
- 内容变多时增高。
- 不遮挡关键卡片操作。
- 占位文案使用真实命令入口语气，例如“输入纠正指令、补充材料或临时协查要求”。

上传文件按钮：

- 使用纸夹或附件语义图标。
- 不使用加号图标表达上传。
- 点击后打开系统文件选择器。

## 语音输入

语音输入只表现收音状态。

交互规则：

- 左侧细栏有麦克风图标控件。
- 指令坞内也有麦克风图标按钮。
- 点击后进入收音样式。
- 收音状态用脉冲环、声波条或按钮高亮表达。

## 选中联动

页面中有三类可选中对象：

- 任务。
- 协作流节点。
- 业务卡片。

联动规则：

- 选任务，高亮对应协作流节点和卡片。
- 选协作流节点，高亮对应任务和卡片。
- 选卡片，高亮对应任务和协作流节点。
- 没有卡片的任务只联动任务和协作流节点。

同一组对象使用同一种强调色。强调色克制，不闪烁。

## 状态语言

常用状态：

- 待接入。
- 处置中。
- 等待。
- 执行中。
- 已完成。
- 失败。
- 待补救。
- 已停止。
- 不处置。
- 只读回放。

状态表达方式：

- 顶部状态灯表达全局状态。
- 任务图标表达执行状态。
- 待办状态条表达队列状态。
- 协作流节点表达事件状态。
- 卡片边框表达选中或异常。
- 历史回放通过弱化指令入口和只读状态表达。

颜色只是一部分。形态、透明度、边框、节点、图标和位置共同参与状态表达。

## 文案语言

页面文案使用真实业务语言。

允许出现：

- 警情名称。
- 指挥长姓名。
- 区域。
- 时间。
- 任务标题。
- 任务失败摘要。
- 用户指令。
- 系统自然语言回复。
- 业务卡片内容。

不出现：

- 工程字段。
- 工程说明。
- 模块占位说明。
- 教学式功能说明。
- 与业务无关的状态文案。

## 动效语言

适合使用：

- 新警情事件轻微滑入。
- 侧边区域展开、收起、左右吸附的平滑动效。
- 收纳把手 hover 和拖拽反馈。
- 指令坞底部上浮。
- 任务从等待到执行中的轻微脉冲。
- 失败状态短暂强调后稳定。
- 语音收音时的脉冲或声波。

不适合使用：

- 大幅缩放。
- 长时间闪烁。
- 大面积扫描线。
- 过强霓虹光效。
- 与业务状态无关的装饰动画。

## 窄视口

窄视口下：

- 左侧细栏保持固定。
- 顶部信息可换行。
- 业务卡片单列排布。
- 侧边区域作为覆盖抽屉出现。
- 指令坞不造成横向溢出。
- 所有按钮仍可点击。
- 文本不重叠、不溢出容器。

移动端保持可读、可操作、无明显错位。
